# Zuno

## What it does

A timer app that tracks time across time zones: a world map with a location icon and the local time
for each place, a month grid of weekends and public holidays, and a meeting-time picker for the
places you add. The map and the month grid are one rounded card, the picker is a card beside it, and
each of those two cards ends with a legend of its colours. Each place is a city from a fixed list
of 55 cities, and you can choose its weekend days (the default is its country's weekend). The
settings panel holds the places,
the working hours, the display switches and the theme (Light, Dark, or Auto, which follows your
system). You can add a public holiday the holiday service does not list (by country, date and
name), remove it, and hide a listed holiday from its card in the month grid and show it again from
the settings panel. Your added and hidden holidays are saved in the browser. "Export" in the
Holidays section saves them to a file (`zuno-holidays.json`) that you can share, and "Import" adds the
holidays of such a file to your own; a file that is not a Zuno holidays file is refused and nothing
changes. Both use local files only.

## Stack

Plain JavaScript, HTML and CSS, bundled into one file by esbuild 0.28.2. Browser tests use Playwright 1.65.1 (dev-only). The holiday table is generated with date-holidays 3.39.2 (dev-only; the page does not include it). Versions of every tool are in `package.json`.

## Setup

```bash
npm install
npx playwright install chromium firefox webkit
```

The second command downloads the three browsers that the browser tests drive. The fourth, Microsoft
Edge, is not downloaded: the tests use the Edge installed on the machine (the `msedge` channel). The
page needs no configuration and no server.

After a fresh clone, turn on the pre-commit hook, which refuses a commit unless the checks pass:

```bash
git config core.hooksPath .githooks
```

## How to run

Build the one-file page, then open `dist/zuno.html` in a browser:

```bash
npm install
npm run build
```

### The built-in holiday table

The holiday service has no data for India, Israel, Malaysia, Pakistan, Saudi Arabia, Taiwan and
the United Arab Emirates, so their public holidays come from `data/holiday-table.js`, which is built into the page: the page asks
the holiday service nothing for these countries. The table covers the years 2026 to 2028; for a later
year these countries appear in the "Some holiday data is missing" notice until you add holidays or make the table
again. The settings panel's Holidays section carries the credit for the data. The file is
generated; never edit it by hand. To make it again (for example before 2029, when it runs out):

```bash
node scripts/make-holiday-table.mjs
```

The script uses the dev-only library `date-holidays` (installed by `npm install`). Islamic holidays
in the table are calculated and can be a day off the official announcement.

## How to test

```bash
npm test
npm run typecheck
npm run lint
npm run lint:css
npm run format:check
```

`npm test` also runs the headless-browser tests in `tests/e2e/ui/`. They build the page into a
scratch folder, open it as a file in Chromium, Firefox, WebKit and Edge, and answer the holiday
service by request routing, so they need no network.

`npm test` also measures coverage of `src/` and fails below 80% for lines or branches.
