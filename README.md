# Zuno

Meeting times, weekends and public holidays across time zones, in one page.

[![Open Zuno](https://img.shields.io/badge/Open-Zuno-12B886?style=for-the-badge)](https://alkashef.github.io/zuno/)
[![Download zuno.html](https://img.shields.io/badge/Download-zuno.html-0F4C5C?style=for-the-badge)](https://github.com/alkashef/zuno/releases/latest/download/zuno.html)

## Use Zuno

- **Online:** open https://alkashef.github.io/zuno/. Nothing to install.
- **Download:** get [zuno.html](https://github.com/alkashef/zuno/releases/latest/download/zuno.html)
  and double-click it to open it in your browser. It is one file: you can share it by email or on a
  shared drive. It is rebuilt on every change; the settings panel shows its version.
- **Install as an app:** open the online page, then use your browser's own menu. In Chrome, choose
  Cast, save and share, then Install page as app. In Edge, choose Apps, then Install this site as an
  app. In Safari on a Mac, choose File, then Add to Dock. Zuno then opens in its own window.

Your places, settings and holidays stay in your browser; nothing is sent anywhere except the
country and year asked of the public-holiday service. The online page, an installed app and a
downloaded file each keep their own settings. Use Export and Import in the settings'
Holidays and vacations tab to carry your holidays between them.

## What it does

A timer app that tracks time across time zones: a world map with a location icon and the local time
for each place, a month grid of weekends, public holidays and vacations, and a meeting-time picker for the
places you add. The map and the month grid are one rounded card, the picker is a card beside it, and
each of those two cards ends with a legend of its colours. The cards fill the window from edge to
edge. Drag the picker's left edge to show more hours, and drag the border between the map and the
month grid (or focus it and press the up and down arrow keys) to give the map more or less room;
the browser remembers both. Each place is a city from a fixed list
of 55 cities, or a custom place that you add in the Places tab with "A person or another city": a
name (a person's, if you like), a time zone and a country or territory. You can choose the weekend
days of any place (the default is its country's weekend), and the Holidays form offers the country of
each custom place. The
settings cover the whole page and have three tabs: General (the working hours, the display
switches and the theme: Light, Dark, or Auto, which follows your system), Places (add a place and
the list of places) and Holidays and vacations. The Close button or Escape closes them. Point at a holiday or vacation day in the month grid (or move the focus to it) and a card
beside the place's name shows its name and dates. Right-click any day to open a menu: "Add public holiday…"
asks for a name and adds the holiday, with the date you clicked, for that place's country; on a holiday day the
menu also has "Hide public holiday", or "Remove public holiday" for one you added. The settings also
add a public holiday the holiday service does not list (by country, date and name), remove it, and show a hidden holiday again. Your added and hidden holidays are saved in the browser. "Export" in the
Holidays and vacations tab saves them to a file (`zuno-holidays.json`) that you can share, and "Import" adds the
holidays of such a file to your own; a file that is not a Zuno holidays file is refused and nothing
changes. Both use local files only. The settings panel ends with the version: the word "Version" and the
date and time of the build in UTC (for example 2026.11.18.1432), so you can tell which build a copy
is. Two builds of the same code have different versions.

## Stack

Plain JavaScript, HTML and CSS, bundled into one file by esbuild 0.28.2. Browser tests use Playwright 1.65.1 (dev-only). The holiday table is generated with date-holidays 3.39.2 (dev-only; the page does not include it). Versions of every tool are in `package.json`.

## Setup

```bash
npm install
npx playwright install chromium firefox webkit
```

The second command downloads the three browsers that the browser tests drive. The fourth, Microsoft
Edge, is not downloaded: the tests use the Edge installed on the machine (the `msedge` channel). The
page needs no configuration and no server.

After a fresh clone, turn on the pre-commit hook, which refuses a commit unless the checks pass:

```bash
git config core.hooksPath .githooks
```

## How to run

Build the one-file page, then open `dist/zuno.html` in a browser:

```bash
npm install
npm run build
```

### The built-in holiday table

The holiday service has no data for India, Israel, Malaysia, Pakistan, Saudi Arabia, Taiwan and
the United Arab Emirates, so their public holidays come from `data/holiday-table.js`, which is built into the page: the page asks
the holiday service nothing for these countries. The table covers the years 2026 to 2028; for a later
year these countries appear in the "Some holiday data is missing" notice until you add holidays or make the table
again. The settings' Holidays and vacations tab carries the credit for the data. The file is
generated; never edit it by hand. To make it again (for example before 2029, when it runs out):

```bash
node scripts/make-holiday-table.mjs
```

The script uses the dev-only library `date-holidays` (installed by `npm install`). Islamic holidays
in the table are calculated and can be a day off the official announcement.

Licence: the table's data comes from `date-holidays`
(https://github.com/commenthol/date-holidays) and is under CC BY-SA 3.0
(https://creativecommons.org/licenses/by-sa/3.0/). The library's code is ISC.

### The map's coastlines

The map's outline is Natural Earth's 1:110m land data (`data/ne_110m_land.geojson`, public domain,
https://www.naturalearthdata.com/). `npm run build` puts the outline path
(`data/map-outline.svg`) into the page; the page itself loads nothing for the map. Both files are
committed, so you need the commands only to change them. The generated file is never edited by hand:

```bash
node scripts/make-map.mjs --download   # fetches ne_110m_land.geojson into data/ (the only network use)
node scripts/make-map.mjs              # writes data/map-outline.svg from it
```

### The time zones of custom places

A custom place (a person, or a city that is not in the list) has a name, a time zone and a country or
territory. The time zones, the map position of each (its reference city) and the country codes come
from IANA's tz database files `data/zone.tab` and `data/iso3166.tab` (public domain,
https://www.iana.org/time-zones). `scripts/make-zone-table.mjs` turns them into
`data/zone-table.js`, which `npm run build` puts into the page. All three files are committed, so
you need the commands only to change them. The generated file is never edited by hand. A zone that
one of the four browsers refuses goes on the script's skip list (`skippedZones`):

```bash
node scripts/make-zone-table.mjs --download   # fetches zone.tab and iso3166.tab into data/ (the only network use)
node scripts/make-zone-table.mjs              # writes data/zone-table.js from them
```

## How to publish

Every push to `main` publishes the page to GitHub Pages: the workflow in
`.github/workflows/pages.yml` builds `dist/zuno.html`, deploys it as the site's `index.html`, and
attaches the same file to the GitHub Release `latest` (made again at the pushed commit), which is
where the README's download link points.
The repository's Settings, Pages must have the source "GitHub Actions". The site's address is
https://alkashef.github.io/zuno/. To publish again without a new commit, run the workflow "Publish
to GitHub Pages" from the repository's Actions tab.

The same file also runs from the local desktop: build it and open `dist/zuno.html` in a browser.
The page on GitHub Pages and a copy opened from disk each keep their own saved settings and
holidays; use the Holidays section's export and import to carry holidays from one to the other.

## How to test

```bash
npm test
npm run typecheck
npm run lint
npm run lint:css
npm run format:check
```

`npm test` also runs the headless-browser tests in `tests/e2e/ui/`. They build the page into a
scratch folder, open it as a file in Chromium, Firefox, WebKit and Edge, and answer the holiday
service by request routing, so they need no network.

`npm test` also measures coverage of `src/` and fails below 80% for lines or branches.
